From Local-First to Full-Stack

I've always been a fan of local-first software. Applications that work offline, don't depend on external servers, and let users access their data without constantly needing an internet connection have always appealed to me.

Projects like CampusCrave and my other experiments have shaped how I approach software development. I generally prefer keeping things simple, accessible, and independent of unnecessary infrastructure.

But eventually, I realised something: Not every application is meant to be local-first.

Some software genuinely needs a database, user authentication, synchronisation, and a proper backend infrastructure. And that got me thinking: why not build one myself?

This became an opportunity to take a step further into full-stack development. What started as an experiment turned into one of my most significant development milestones: building a production-oriented full-stack application in approximately one day.

Why Full-Stack?

Local-first development has its advantages, but it also has limitations.

When an application needs multiple users, shared data, persistent accounts, and synchronisation across devices, a local-only architecture isn't always the right solution.

I wanted to experience the other side of software engineering. Not just building interfaces, but handling the infrastructure behind them.

I wanted something that wasn't merely a frontend demonstration or a static website. I wanted an application that could actually function as a real product.

The Tech Stack

I chose technologies that allowed me to move quickly without compromising the flexibility of the application.

- Frontend & Application Framework: Next.js
- Database & Backend Infrastructure: Firebase
- Development Approach: AI-assisted development using modern vibe coding tools

Next.js provided the foundation for the application, while Firebase handled the database infrastructure and backend services.

It was a combination that allowed me to focus on building the actual product rather than spending all my time setting up infrastructure from scratch.

The Reality of Building Full-Stack Software

This was where things got interesting.

Building the frontend was one thing. Making everything work together was another.

Database configuration, authentication, authorisation, environment variables, deployment, hosting restrictions, free-tier limitations, and unexpected paywalls all became part of the development process.

Things that worked perfectly in my local development environment didn't necessarily behave the same way once deployed.

I encountered limitations I hadn't initially considered. Certain services had restrictions, some features required paid plans, and some architectural decisions needed to be reconsidered.

It wasn't as straightforward as I had imagined.

But that's part of the experience. Software development isn't just about writing code. It's also about understanding the ecosystem, making compromises, and finding practical solutions within real-world constraints.

Security Wasn't Optional

This was probably the part I took most seriously.

When an application starts handling user accounts and remotely stored information, security becomes a fundamental responsibility.

A database isn't simply a place to store information. It's one of the most sensitive components of an application.

Poorly configured database permissions can expose private information, allow unauthorised access to other users' records, and potentially create pathways to account compromise.

I didn't want to release something that looked great on the surface but had fundamental security problems underneath.

I therefore dedicated time to reviewing the application's security, including authentication, authorisation, database access policies, input handling, and other potential vulnerabilities.

I also conducted a dedicated security audit covering:

- Authentication and authorisation.
- Cross-Site Request Forgery (CSRF).
- Cross-Site Scripting (XSS).
- SQL injection and command injection.
- Cryptographic practices.
- File upload security.
- API security.
- Defensive programming.

The audit was read-only, and I wanted to understand the application's actual security posture rather than simply assume that using established technologies made it secure.

There is still room for improvement, and I'm working towards addressing those areas.

Security isn't a feature you implement once and forget about. It's an ongoing responsibility.

Building Faster with AI

Another major part of this experience was AI-assisted development.

Tools commonly associated with vibe coding have significantly changed how quickly I can turn ideas into functional software.

Prototyping, exploring implementations, debugging, and iterating on interfaces have become considerably faster.

Building a substantial full-stack application in approximately one day would have been a much more demanding undertaking without these tools.

However, I don't believe that generating code automatically makes someone a good developer.

There is a significant difference between generating code and understanding what that code actually does.

I still need to understand the architecture, evaluate implementation decisions, identify security issues, and ensure that everything works as intended.

AI accelerated the development process, but engineering judgement remained essential.

One Day. A Major Milestone.

I've built countless applications and experimented with several full-stack projects before. Some never made it to release, while others were developed in different contexts where I wasn't necessarily credited as the developer.

This project felt different.

It was something I could build, own, improve, and present as part of my own developer portfolio.

Completing such a substantial application in approximately one day was a milestone I genuinely didn't expect to achieve so quickly.

Is it perfect? Absolutely not.

There are limitations, improvements to make, and features I'd still like to refine. But it's functional, it's a significant step forward, and I'm genuinely proud of what I've accomplished.

What's Next?

My goal has always been to become a stronger full-stack developer.

Although I've already worked across different areas of application development, I don't want to stop at knowing how to connect a frontend to a database.

I want to understand infrastructure, security, deployment, scalability, performance, and the engineering decisions that make software reliable in the real world.

This project has given me a much better appreciation of what goes into building and maintaining a full-stack application.

I'll continue improving it, auditing it, and working towards making it better.

I don't necessarily expect perfection, but I do want to get as close as practically possible.

A Final Thought

Building software isn't just about making something that works.

It's about making something reliable, maintainable, secure, and useful to the people who depend on it.

I started this journey as someone who generally preferred local-first applications. I'm ending this particular development milestone with a much better understanding of why full-stack architecture matters and the responsibilities that come with it.

Built with curiosity, accelerated with AI, and improved through engineering.
