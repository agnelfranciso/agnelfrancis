If you have ever asked an AI coding assistant to generate a PDF, you already know how frustrating the result usually is.

Either it spins up an entire Next.js or React project just to print two pages of text, or it dumps raw HTML into a converter that slices cards in half across page boundaries, clips wide TypeScript code blocks off the right margin, drops background colors, and leaves awkward empty gaps at the bottom of every page.

I wanted a clean, deterministic, portable solution that works across **any AI agent**—Antigravity, Claude Code, Cursor, Codex, or Gemini CLI—without heavy JavaScript frameworks. So I built **`pdf-maker`**, an open-standard skill following the [agentskills.io](https://agentskills.io) specification.

## Why Most AI-Generated PDFs Break

When LLMs write raw HTML and CSS from scratch for print, four predictable failure modes happen:

1. **Fragmented Cards & Orphan Headings**: Without `break-inside: avoid` and `break-after: avoid`, headings sit alone at the bottom of a page while their content jumps to the next, and Chromium's flexbox/grid pagination bugs still slice containers mid-border.
2. **Clipped Code & Missing Table Headers**: Multi-page tables forget `<thead>` repetition, and `<pre>` blocks overflow horizontally instead of wrapping cleanly.
3. **Stripped UI Colors**: Headless browsers strip background fills from badges, dark banners, and table headers unless `print-color-adjust: exact` is enforced.
4. **One-Size-Fits-All Templates**: A formal medical leave application to a Head of Department should look like a crisp institutional letter—not a SaaS analytics dashboard with KPI cards and progress bars. Conversely, a university assignment or technical spec benefits from a dedicated front cover page, table of contents, syntax-highlighted code windows, and diagrams.

## The Architecture: Declarative JSON DSL + Print-Safe CSS3

Instead of asking the AI agent to write fragile HTML boilerplate every time, **`pdf-maker`** introduces a declarative **JSON Document DSL (`doc.json`)** compiled by a zero-dependency Python engine into print-safe HTML5 and CSS3, then rendered via auto-detected **Playwright, headless Chrome/Edge, or WeasyPrint**.

```json
{
  "title": "Routing Information Protocol (RIP)",
  "theme": "pulse",
  "page_size": "A4",
  "margin": "13.5mm",
  "page_numbers": true,
  "blocks": [
    {
      "type": "cover",
      "badge": "COMPUTER NETWORKS • ASSIGNMENT 03",
      "title": "Routing Information _Protocol_ (RIP)",
      "subtitle": "Distance-Vector Routing & Bellman-Ford Mechanics"
    },
    {
      "type": "code",
      "lang": "typescript",
      "title": "rip_bellman_ford.ts",
      "highlight_lines": [3, 4],
      "code": "const MAX_HOPS = 15;\nexport function nextCost(hops: number): number {\n  return Math.min(hops + 1, MAX_HOPS + 1);\n}"
    }
  ]
}
```

### Key Features Built Into the Skill

- **15+ Programming Languages Syntax Highlighting**: A built-in pure-Python tokenizer renders **TypeScript/TSX, JavaScript/JSX, Python, SQL, Rust, Go, Bash/PowerShell, JSON, YAML, HTML, CSS, Java, and C/C++** inside macOS-style code windows with line numbers, highlighted lines, and `white-space: pre-wrap` wrapping.
- **International & RTL Support**: Full UTF-8 support (`lang` and `dir="rtl"`) with `Inter Tight`, `Instrument Serif`, `JetBrains Mono`, `Noto Sans Arabic`, `Noto Sans SC`, and emoji font stacks.
- **Document-Type Blueprints**: Built-in structural rules guide the agent to choose `letterhead` + `address` + `subject` + `signature` for formal letters, `cover` + `toc` + `cards` + `code` for academic assignments, and `kpis` + `chart` + `table` for engineering/executive reports.
- **Consistent `Page X of Y` Numbering**: Passing `--page-numbers` or setting `"page_numbers": true` stamps uniform page footers across Chrome, Edge, Playwright, and WeasyPrint.

## Print-Safe Image & Gallery Embedding

Images are one of the easiest ways to break a PDF layout—relative paths fail inside temporary build directories, oversized screenshots push across page boundaries, and captions detach from their figures.

In `pdf-maker`, local PNG, JPG, WebP, and SVG files passed to `"type": "image"` or `"type": "gallery"` are automatically:

1. Resolved relative to the document directory and **embedded as Base64 data URIs** so they never break across rendering engines.
2. Constrained with `max-width: 100%`, `max-height: 135mm`, and `object-fit: contain`.
3. Wrapped inside a `<figure>` container with `break-inside: avoid` so an image and its caption always stay together.

## Automated Pixel-Level QA Before Delivery

Generating a PDF isn't enough—the skill also verifies that the rendered pages actually look right. `inspect_pdf.py` renders every PDF page to a PNG and scans the raw pixel buffer to catch layout regressions automatically:

- **Bottom Gap Detection**: Scans rendered rows from bottom to top and warns if more than `42%` of a content page is empty trailing whitespace (usually caused by a tall `break-inside: avoid` block or misplaced `page_break`).
- **Sparse Page Detection**: Flags near-empty trailing pages with fewer than `25` words or under `8%` vertical ink fill.
- **Horizontal Edge-Clipping Check**: Scans the outer `1.5%` left and right margin bands for overflowing tables or code lines.

Every generated document goes through both this automated pixel check and a visual inspection of the rendered PNGs before it reaches the user.

## Download & Use It in Your Agent

The skill is open source under the MIT License and packaged as a ready-to-extract `.zip` release:

- **GitHub Repository**: [github.com/agnelfranciso/pdf-maker-skill](https://github.com/agnelfranciso/pdf-maker-skill)
- **Download Release ZIP (`v2.0.0`)**: [github.com/agnelfranciso/pdf-maker-skill/releases/latest](https://github.com/agnelfranciso/pdf-maker-skill/releases/latest)

To install it in **Antigravity, Claude Code, Cursor, Codex, or Gemini CLI**, download `pdf-maker-v2.0.0.zip` and extract the `pdf-maker/` folder into your skills directory (`.agents/skills/`, `.claude/skills/`, `.cursor/skills/`, or `.gemini/skills/`).

If you try it out or have ideas for new document blocks or themes, feel free to open an issue on GitHub or reach out via the [Contact](/contact) page!
